Closures（闭包）

Autoclosures（自动闭包）算是闭包里比较小众的一种语法。知道它是有好处的，不过你不会经常自己写使用 autoclosure 的函数。

  • Autoclosures（自动闭包）

Enumerations（枚举）

我们大概还是想避免递归枚举，所以本周再次把它留到以后。

  • Recursive Enumerations（递归枚举）

Properties（属性）

属性观察器很简单（下周课上我们会展示）。另一方面，属性包装器稍微更难理解，但它们非常重要，因为正是这种语言特性支撑了 @State、@Published、@ObservedObject 等东西。尽力理解属性包装器是如何工作的，但不要觉得自己必须已经掌握到能亲手编写属性包装器的程度。

  • Property Observers（属性观察器）
  • Property Wrappers（属性包装器）

Subscripts（下标）

下标常常是一种很干净的语法，可以用来访问集合中的数据，甚至也可以从某个非结构化数据源中按语义取出一个值。话虽如此，在你学习 Swift 的前 10 周里，它大概不是你会经常自己写的东西。请阅读整个小节。

Inheritance（继承）

我们会比较轻描淡写地带过 Swift 中的面向对象编程，因为除了 @Observable 之外，你在 SwiftUI 中不会经常用到它。我们会把这部分阅读放到第 4 次也是最后一次阅读作业里（那一次主要会是一些“偏门知识”）。

Initialization（初始化）

同上，关于 OOP 的部分暂时略过。这里我们只读最后一个非面向对象的初始化主题：可失败初始化器。可失败初始化器其实相当常用。基本上，它只是允许某个 init 函数返回一个 Optional；如果无法根据提供的参数初始化这个 struct 或 class，就返回 nil。

  • Class Inheritance and Initialization（类继承与初始化）
  • Failable Initializers（可失败初始化器）
  • Required Initializers（必需初始化器）

Deinitialization（反初始化）

反初始化也是另一个 OOP/引用类型相关主题。

Error Handling（错误处理）

理解错误处理很重要，尤其是当你逐步接触 Swift 和 SwiftUI 中更强大的 API 时。事实上，错误处理和并发是本周阅读里最重要的主题。请阅读整个小节。

Concurrency（并发）

并发很重要，因为我们不希望轻快灵敏的 UI 被慢吞吞的活动阻塞，例如网络获取、处理大批量机器学习数据，或诸如此类的事情。请阅读整个小节。

Macros（宏）

这一节解释了像 @Observable 这样的东西实际上是如何实现的。现在我们可以先把它们当作“魔法”。我们会把这一节安排到下周。

Type Casting（类型转换）

随着 SwiftUI 完全取代 UIKit 成为人们编写 iOS app 的方式，类型转换变得越来越不必要。所以我们会把这块灰掉，留到最后一次阅读作业。一般来说，一个结构良好的 Swift 应用不应该使用任何类型转换；但偶尔为了和 UIKit 时代的 API 做向后兼容，你还是会看到它。如果你在其他语境中发现自己正在做类型转换，通常会有更好的办法，往往是通过协议和泛型。

Opaque and Boxed Protocol Types（这解释了 “some View”）

如果你希望在 API 中表达“我要传来传去的东西表现得像某个协议”，但又不想对那个东西施加其他限制，这种能力非常有价值。不透明类型（Opaque types）就允许你这么做。这大概属于“相对高级的函数式程序员会用的工具”这一类；你很可能即使没有完全掌握它，也能正常写 SwiftUI app。但当你在代码中看到 some View 之类的东西时，你至少应该知道发生了什么。

理解 some Shape 和 any Shape 之间的区别很重要，所以请认真留意。

Automatic Reference Counting（自动引用计数）

这是引用类型的内存被清理的方式。再说一次，我们主要使用值类型，所以可以把这部分推迟到最后一次阅读作业。

Memory Safety（内存安全）

哎呀，如果你必须关心自己会不会在堆内存里乱踩内存，那你真的已经到达 Swift 风格的外缘了！在正常编写 SwiftUI 应用的过程中，你应该永远不必担心这个。

Access Control（访问控制）

我们其实只是为了降低你的阅读负担，才把这部分推迟到现在。注意，在你开始编写自己的模块（Swift 里的说法，也就是代码库）之前，许多访问控制关键字（比如 public）都不会是你会用到的东西。private、private(set)（以及默认的 internal）会是你最常用的访问控制级别。

  • Initializers（初始化器）
  • Protocols（协议）
  • Extensions（扩展）
  • Generics（泛型）
  • Type Aliases（类型别名）
