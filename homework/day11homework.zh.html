Deinitialization（反初始化）

同上，关于 OOP。

Macros（宏）

宏是最近加入 Swift 的，它为 Apple 提供了一种相对干净的机制，让你能把注意力更多放在自己代码的细节上，而不必担心底层机制（例如“当 @Observable 中的某个 var 变化时，一个 SwiftUI View 是怎么知道自己必须更新的？”）。本周你会阅读这些东西实际上是如何工作的。我怀疑你短期内不会创建自己的宏，但至少你会知道这是可能的。

Type Casting（类型转换）

随着 SwiftUI 完全取代 UIKit 成为人们编写 iOS app 的方式，类型转换已经变得越来越不必要。一般来说，一个结构良好的 Swift 应用不会大量使用类型转换；不过，我们偶尔会在与 UIKit 时代 API 向后兼容时看到它，而且当我们把 any 和协议一起使用时，也可能会用到它（为了拆箱并取得实际类型）。如果你在其他语境中发现自己正在做类型转换，通常会有更好的办法，往往是通过协议和泛型。

Protocols（协议）

这些剩余的协议主题都与 UIKit 的向后兼容有关。

  • Delegation（委托）
  • Class-Only Protocols（仅限类的协议）
  • Optional Protocol Requirements（可选协议要求）

Automatic Reference Counting（自动引用计数）

这是引用类型清理内存的方式。由于绝大多数时候我们都使用值类型，所以这主要只是为了让你大致理解 Swift 如何在堆上分配内存。
